# 用豆包生成测算网页的分步提示词

[下载 TXT 复制版](分步提示词.txt)

四个开发步骤对应六条消息，每次只发一条。先复制“复制开始”和“复制结束”之间的正文，等结果符合本条检查项再继续。
第 01、02 条定需求，第 03、04 条开发，第 05 条在发现偏差时使用，第 06 条留手册。

## 01 第一步  让豆包阅读客户资料

准备好“交给豆包”工作副本，已把需求、样表和图提供给豆包。

```text
请阅读当前项目里的会议需求摘要、会后补充任务、四份 Excel 和三张参考图。先别写代码。假如明天坐在客户面前，最后一屏你准备给他看什么？要算出这些结果，前面分别要填哪些数？帮我在表里找到它们，拿不准的地方列出来问我。区分云栖和晴川，并说明同一项目的两份表怎样核对。
```

**核对结果**　回答中列出需要的结果、输入字段、来源和待确认的问题；区分两个项目。

**接下来**　看过豆包的问题，确定本次选云栖，再发 02。

## 02 第一步  确认项目与口径

你和豆包已经对齐哪些数要算、哪些仍需确认。

```text
本次演示选云栖生活广场。01 和 04 是同一项目，算法和单位以 04 为准。客户要看项目赚不赚钱，还要能回到上一步追问数字。请把界面设计为六步录入、第七步出结果：项目概况、体量与单价、收入假设、人员编制、设备维保损耗、运营与税费、测算结果。每步只展开当前表单，显示相关小计，返回时保留输入。汇报人可以点“自动演示录入”，让当前数据按相同步骤走到同一个结果；中途点顶部步骤就停止自动翻页。请把输入字段、数据来源、对应结果和验收动作写进项目内的“需求.md”，让我先确认。
```

**核对结果**　拿到一份需求.md，包含六步录入、第七步结果、手动和自动的验收动作。

**接下来**　逐项确认需求，再发 03。

## 03 第二步  请豆包代写开发提示词

需求已经确认，你准备把它转成一条明确的开发指令。

```text
根据刚确认的需求，给我一段可以直接让你生成这个网页的完整提示词。包含七步布局、需要的字段和交互、云栖 Excel 计算口径、离线图表、手动和自动两条验收路径。先给我看提示词。
```

**核对结果**　提示词包含七步顺序、收缴率和费用口径、离线图表及两条验收路径。

**接下来**　读一遍，漏项请它补全；同意开工再发 04。

## 04 第二步  生成离线网页

你已经看过并确认豆包写的开发提示词。

```text
就按你刚才整理、我们确认的提示词动手。请在当前项目里创建“汇报网页”文件夹，把可以双击打开的 index.html、样例数据和所有运行资源放进去，包括随资料提供的本地 echarts.min.js。页面预填云栖的教学数据，允许修改；读取打包的本地数据，断网也能打开。风格参考两张布局图。用 ECharts 画年收入和年成本费用仪表盘、收入柱状图、成本环形图和收缴率曲线。显示盈亏文字、净利润、净利润率、保本保利。收缴率只作用于对应收入，费用按教学表计一次；保留原精度，最后格式化。结果用公式求出。做好告诉我双击哪个文件、如何按 Excel 核对。
```

**核对结果**　收到可打开的 HTML 和本地依赖；双击后实际上能点到第七步。

**接下来**　亲自跑手动和自动两条路，按表复核，然后决定是否需要 05。

## 05 第三步  有偏差时定位和复测

你已复现问题。先把方括号换成自己的动作、实际和期望。

```text
我测试的项目是云栖生活广场。我的操作是【动作】，我看到【实际画面或数值】，按【需求条目或 04 表的工作表和单元格】应该是【期望结果】。请查原因并修复，同时保留其他已验证的行为。告诉我改了什么、刷新后如何复测。
```

**核对结果**　拿到修复说明后，自己复测原动作，再复测此前通过的一组。

**接下来**　如仍有偏差，补上新现象；两条路径都通过后发 06。

## 06 第四步  让豆包留下交接手册

网页已经实际跑过，你手上有测试的数值与现象。

```text
请在“汇报网页”文件夹里写一份开发手册。开头先写怎么打开、手动录入和自动演示怎么用，再写需求来源、七步设计、Excel 和图表字段如何对应、本轮改了什么。若本次实际出现过故障，再写测试手册，记录真实操作、实际结果、修复和我已复测的结果。没有验证过的项目写“待验证”。
```

**核对结果**　手册写了打开方式、现场操作和数据来源；故障记录区分实际修复和待验证。

**接下来**　把整个网页目录交给同事，用一份空白清单让他独立演示。
