# Windows 本地文件加密工具 — 需求文档（REQUIREMENTS）

> 本文档面向**下一步负责实现的 AI / 开发者**，只描述需求、约束与验收标准，不包含应用代码。
> 实现前若发现本文档未覆盖的范围问题，**先向需求方确认，不要自行扩大范围**。

## 0. 范围与技术栈

- **产品形态**：Windows 本地运行的桌面应用，打开后通过简单的图形窗口操作，全程手动选择，不做后台/无人值守任务。
- **用途限定**：仅用于本课程**小体积样例**的原型验证，不是生产级、企业级或面向大文件/批量场景的产品。
- **运行环境**：Windows，使用本机已核实可运行 tkinter 与 cryptography 的 Python。原录制项目使用 Python 3.13.17 / Tk 8.6.15。
  注：原录制机器在密码框退格时发生闪退，并通过更换项目环境复测。此处仅记录该机案例，不能据此认定所有电脑或输入法都会出现相同问题。
- **GUI 框架**：`tkinter`（Python 标准库自带，不引入额外 GUI 依赖）。
- **加密库**：`cryptography`（成熟第三方库）。**必须使用成熟、公开的算法与库，禁止自行发明或拼凑加密算法**。
- **处理范围**：只处理用户在界面上**明确选择**的单个文件或文件夹；**禁止自动扫描、递归遍历或处理任何未被选中的其他路径**。

---

## 1. 目标

1. 对用户手动选中的**单个文件或文件夹**进行加密，生成一个加密包，输出到用户选定的位置；**原件始终保留**，不删除、不移动、不修改。
2. 对加密包进行解密，将文件还原到用户选定的**空目录或新建输出目录**。
3. 加密文件夹后，解密/恢复必须**完整保留子目录结构**。
4. 支持可选的**恢复**能力：用独立的恢复密码解锁已启用恢复的包；**不存在通用密码或后门**。
5. 密码等敏感信息**不得出现在提示、源码、日志或测试报告中**。
6. 任何情况下都**不覆盖原件或已有输出**。

---

## 2. 操作流程

### 2.1 加密流程

1. 用户在窗口中手动选择要加密的对象：**单个文件**或**一个文件夹**（二选一）。
2. 用户设置**文件密码**（用于正常解密）。
3. 用户**可选**填写一条**提示（hint）**：
   - 提示为**明文可见**字段，仅用于帮助用户回忆，不参与加密。
   - **禁止在提示中放入密码**；系统不得把密码自动写入提示。
4. 用户**可选开启“恢复”**：
   - 开启后需**另设一个恢复密码**，该密码独立于文件密码。
   - 未开启则该加密包不存在恢复解锁路径。
5. 用户选择**输出位置与加密包名称**。
6. 确认后生成加密包：
   - 选中文件夹时，其内部所有文件与**子目录结构**一并装入加密包，还原后目录层级不变。
   - 加密完成后**原件原样保留**。
   - 目标位置若已存在同名输出，**不得覆盖**（见第 3 节）。

### 2.2 解密流程

1. 用户手动选择一个**加密包**。
2. 在输入密码**之前**，用户可以查看该包保存的提示：
   - 界面必须明确标注“**提示可见**”，让用户清楚该字段是可见、非保密的。
   - 若该包没有提示，则相应区域显示无提示。
3. 用户输入文件密码：密码输入框必须**遮挡输入内容**（掩码显示，不可明文回显）。
4. 系统校验并解密：
   - **密码错误**（或包被篡改、无法通过认证）时，给出**清楚、可理解的错误提示**，并且**不得写出任何解密结果/文件**。
   - 解密成功前，不得在磁盘上创建部分解密产物。
5. 用户选择解密目标：必须是**空目录**或由程序/用户**新建的输出目录**；非空目录不得作为直接输出目标。

### 2.3 恢复流程

1. 恢复能力仅对**加密时就已启用恢复**的包有效。
2. 用户选择加密包后，可走“恢复”入口，输入**恢复密码**。
3. **同一个恢复密码**可以打开多个在加密时即为该密码启用恢复的包。
4. 恢复成功后还原的是**文件内容**（含文件夹的子目录结构）；界面**不得显示、回显或导出原文件密码**。
5. 对**未启用恢复**的包使用恢复密码，必须**拒绝并明确提示该包未启用恢复**，无法打开。
6. 系统**没有通用/万能密码**：除该包自身的文件密码与（如已启用的）恢复密码外，不存在任何可解锁的密码。

## 3. 异常情况

| 编号 | 异常场景 | 期望行为 |
|---|---|---|
| E1 | 文件密码错误 | 弹出清晰错误提示；认证失败，**不产生任何解密文件或部分结果** |
| E2 | 加密包被篡改/损坏/无法识别 | 提示包无效或已损坏；认证失败，不写出结果 |
| E3 | 对未启用恢复的包使用恢复密码 | 拒绝解锁，明确提示“该包未启用恢复”，不还原文件 |
| E4 | 输出位置已存在同名加密包/文件 | **不覆盖**，提示用户更换位置或名称后重试 |
| E5 | 解密目标目录非空 | 不直接写入；要求选择空目录或新建输出目录 |
| E6 | 密码为空、两次输入不一致、文件密码与恢复密码相同 | 加密前校验拦截并提示，无法进入下一步 |
| E7 | 提示内容与密码相同（疑似把密码写进提示） | 拦截或明确警告，要求修改提示；提示中不得包含密码 |
| E8 | 未选择对象就确认、中途取消选择 | 友好提示，不崩溃、不产生空任务 |
| E9 | 选择的文件不是有效加密包 | 提示无法识别该文件格式，不尝试解密、不写文件 |
| E10 | 文件被占用、无写入权限、磁盘空间不足等系统错误 | 给出可读的错误提示，不崩溃、不留下半成品输出 |
| E11 | 任何认证/解密失败 | 一律**先失败、不落盘**，禁止“先写出文件再报错” |

## 4. 安全与实现约束

1. **使用成熟算法与库**：通过 `cryptography` 实现，采用带完整性校验的认证加密（使错误密码与篡改都能被检测到）；密钥由密码通过成熟的密钥派生函数（加盐）生成。不得自研算法、不得使用自研或已废弃的加密方案。
2. **不存储明文密码**：文件密码与恢复密码均不得明文保存；只保存用于验证/派生所需的非可逆信息（如盐与认证后的封装数据）。
3. **恢复是独立解锁路径**：恢复密码必须能在**不依赖、不暴露文件密码**的前提下还原文件；界面与数据中都不出现原文件密码。未启用恢复的包不得包含恢复解锁所需的数据。
4. **无通用密码/后门**：不为“管理员”“测试”或任何目的预留万能密码。
5. **密码不落地**：密码不得写入提示字段、源码、日志、临时文件或测试报告；文档与测试中的密码一律用角色/占位符表示（如“正确文件密码”“错误密码”），不硬编码真实密码。
6. **不覆盖**：原件、已有加密包、已有输出目录均受保护，冲突时拒绝并提示，而不是自动替换。
7. **不越界处理**：仅操作用户明确选中的对象，不自动扫描磁盘、不批量处理、不访问其他路径。
8. **失败即停**：解密/恢复在认证通过前不得创建或写入任何输出文件。

## 6. 验收用例

| 编号 | 用例 | 操作 | 预期结果（判定标准） |
|---|---|---|---|
| A1 | 单文件往返 | 加密单个文件，再用文件密码解密 | 解密内容与原件**逐字节一致**；原件仍保留 |
| A2 | 文件夹往返 | 加密含子目录的文件夹后解密 | 子目录层级与所有文件完整还原，内容一致 |
| A3 | 原件保留 | 加密后检查原路径 | 原件未被删除、移动或修改 |
| A4 | 输出不覆盖 | 在已存在同名输出的位置再次加密 | 拒绝写入并提示，原输出文件保持不变 |
| A5 | 错误文件密码 | 解密时输入错误密码 | 清晰报错；目标目录中**无任何解密文件产生** |
| A6 | 密码输入遮挡 | 查看加密/解密密码输入框 | 输入内容被掩码遮挡，不可见明文 |
| A7 | 提示可见且不含密码 | 解密前查看提示、检查界面标注 | 界面标注“提示可见”；能看到提示文本；提示中不含密码 |
| A8 | 恢复成功 | 对启用恢复的包输入恢复密码 | 成功还原文件；界面**不显示原文件密码** |
| A9 | 一密多包 | 用同一恢复密码打开多个为其启用恢复的包 | 多个包均能成功恢复 |
| A10 | 未启用恢复 | 对未启用恢复的包输入恢复密码 | 拒绝并提示未启用恢复，无法还原 |
| A11 | 无通用密码 | 用任意非设定密码尝试解锁 | 全部失败，不存在可解锁的万能密码 |
| A12 | 解密目录约束 | 分别选择空目录、新目录、非空目录 | 空目录/新目录可输出；非空目录被拦截 |
| A13 | 篡改检测 | 改动加密包字节后再解密 | 认证失败并提示，不写出任何结果 |
| A14 | 不越界 | 工作区放置其他文件，仅选中一个样例处理 | 其他文件完全不被读取、修改或处理 |
| A15 | 密码不落地 | 检查源码、日志、测试报告与提示字段 | 均无明文密码/密钥；测试记录使用占位符 |
| A16 | 取消与异常操作 | 取消选择、选择无效文件、制造权限/空间错误 | 友好提示且不崩溃，不产生半成品 |

## 7. 实现前需确认的假设（需求方请核对）

以下为整理时补充的合理约束，如不认可请在实现前指出：

1. **文件密码与恢复密码必须不同**（“另设”按独立密码处理，避免两条解锁路径实际等价）。
2. 当**提示内容与密码相同**时，系统在加密前拦截或强制警告，防止用户把密码写进可见提示。
3. 加密产物为**单个加密包文件**（文件夹在包内归档并保留子目录）；具体扩展名与容器格式由实现方在 README 中说明。
4. 本工具仅面向**小体积样例**，不要求大文件流式处理、多线程批量或性能优化。
